### 4. 프로세스 매니저

- [ ] `infrastructure/outbound/process_manager/manager.rs`
  - `ProcessManager { registry: DashMap<Uuid, LlamaServerProcess>, port_pool, binary,
                     activity, idle, node_repo, settings, aimd_hook }`
  - `ensure_running(model_id) -> Result<ProcessHandle>` — **lazy start 진입점**
    - 라우터/추론 핸들러가 호출
    - 1. Modelfile lookup (Phase 2 modelfile_registry)
       - 미등록 → ModelNotRegistered (라우터 → 404)
       - install_status != 'ready' → ModelNotReady{status, error?} (라우터 → 503/409)
    - 2. registry 에 동일 model_id 의 Ready 인스턴스 있으면 즉시 반환
    - 3. 없으면 → load_model(modelfile) 비동기 트리거 (idempotent: in-flight 면 같은 future)
  - `load_model(modelfile) -> Result<LlmProvider>` — 명시적 사전 로드 + lazy start 공통 경로
    1. ModelStore.resolve_blob(modelfile.blob_sha256) → blob_path
       - Local PV /blobs/{sha256}.gguf 확인
       - 없으면 Garage 에서 streaming fetch + atomic write + sha256 검증
    2. node_selector.pick_node(modelfile, capacity_status='available')  — node_id 명시 시 그대로
    3. binary.check_installed(node)? install(node)
    4. port_pool.allocate(node)
    5. config = LlamaServerConfig { model_id, blob_path, runtime: modelfile.runtime, port, node_id }
    6. process.start(node, config)  — Stopped → Loading → Warming → Ready
    7. on_ready 훅 → AIMD.register(provider_id) (Phase 4 연동)
    8. LlmProvider 자동 DB 등록 (mode='managed', node_id, model_id)
    9. registry.insert
  - `stop(provider_id) -> Result` — idle/unload/명시 모두 동일 경로
    1. on_stopped 훅 → AIMD.unregister(provider_id)
    2. activity.on_stop(provider_id)
    3. process.stop()
    4. port_pool.release(node, port)
    5. DB status='stopped'
  - `list_running() -> Vec<ProcessInfo>` — node_id, last_request_at, idle_for_s 포함
  - `auto_recover()` — 10s 루프, 크래시 감지 후 재시작 (managed 한정)

### 5-A. Lazy start 라우팅 통합 (Modelfile + install_status + 503 정책)

- [ ] `provider_router.rs` (또는 inference 진입점)
  - `dispatch(model_id, request)` 진입 시 분기:
    1. **Modelfile lookup** (modelfile_registry):
       - 미등록 → 404 `{ error: "model_not_registered" }`
       - found → install_status 검증
    2. **install_status 가드**:
       - `pending|downloading|uploading|verifying`
         → 503 + Retry-After + status_url=/v1/admin/models/:id/install/stream
         → body: `{ reason: "model_installing", attempt_no, stage, progress_pct }`
       - `failed`
         → 409 + body: `{ reason: "install_failed", error_kind, error_message,
                          retryable, retry_url: "/v1/admin/models/:id/install/retry" }`
       - `ready` → 진행
    3. **provider 선택** (Phase 1 prefix-aware + Phase 4 AIMD):
       - 같은 blob_sha256 의 Ready 인스턴스 우선
       - 없으면 manager.ensure_running(model_id) 비동기 트리거 → 503 반환
    4. **ProcessState == Stopped**: ensure_running idempotent 트리거
       → 503 + Retry-After + body: `{ reason: "model_loading", model_id, provider_id,
                                       eta_seconds, progress, status_url }`
    5. **ProcessState == Loading|Warming**: 동일 503
    6. **ProcessState == Ready**:
       - activity.on_request_start(provider.id)
       - chat_template + defaults 적용 (modelfile)
       - adapter.infer/stream_tokens
       - activity.on_request_end(provider.id) (finally)
  - 큐 holding 코드 없음

  - 같은 model_id 의 Loading 중 인스턴스 있으면 같은 future 반환 (중복 spawn 방지)
