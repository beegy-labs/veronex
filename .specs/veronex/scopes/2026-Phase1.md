# Scope: 2026-Phase1 — LlamaServer 어댑터

> L2: 승인 필요 | roadmap.md Phase 1 파생 | **Created**: 2026-05-09

## Change Summary

`OllamaAdapter` 의존 없이 llama-server(llama.cpp HTTP 서버)로 추론 가능하도록
`LlamaServerAdapter`와 `ProviderType::LlamaServer`를 추가한다.
Ollama는 레거시로 병렬 유지 (기존 등록 provider 무효화 없음).

## Change Type

Add + Migrate (어댑터 레이어 교체, 도메인 로직 유지)

- `docs/llm/inference/capacity.md` — VRAM 풀 + AIMD

## 핵심 변경 원칙

```
llama-server 특성:
  - 프로세스 시작 시 모델 VRAM 로드 → cold start 없음
  - GET /health → {"slots_idle": N, "slots_processing": M}
  - POST /v1/chat/completions (OpenAI 호환)
  - --ctx-size 프로세스 기동 시 고정 → num_ctx SSOT 정렬 불필요

lifecycle 단순화:
  Before: probe + /api/ps 폴링 + stall 감지 + coalescing (600줄)
  After:  GET /health → ok? → AlreadyLoaded (50줄)

라우팅 기준 변경:
  Before: VRAM 잔량(MB) — /api/ps 30s 주기 갱신
  After:  slots_idle 수 — /health 즉시 응답
```

## LlamaServerAdapter 설계

```rust
// ensure_ready: health check만
async fn ensure_ready(&self, _model: &str) -> Result<LifecycleOutcome, LifecycleError> {
    let slots = self.health().await?;
    match slots {
        SlotStatus::Ok { .. } => Ok(LifecycleOutcome::AlreadyLoaded),
        SlotStatus::Loading    => Ok(LifecycleOutcome::AlreadyLoaded), // 시작 중
        SlotStatus::Failed     => Err(LifecycleError::ProviderError("unhealthy".into())),
    }
}

// stream_tokens: OpenAI SSE
fn stream_tokens(&self, job: &InferenceJob) -> Stream<StreamToken> {
    POST /v1/chat/completions { model, messages, stream: true }
    // data: {"choices":[{"delta":{"content":"..."}}]} 파싱
}

// infer: OpenAI non-streaming
async fn infer(&self, job: &InferenceJob) -> Result<InferenceResult> {
    POST /v1/chat/completions { model, messages, stream: false }
}
```
