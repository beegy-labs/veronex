# Scope: 2026-Phase1 — LlamaServer 어댑터

> L2: 승인 필요 | roadmap.md Phase 1 파생 | **Created**: 2026-05-09

## Change Summary

`OllamaAdapter` 의존 없이 llama-server(llama.cpp HTTP 서버)로 추론 가능하도록
`LlamaServerAdapter`와 `ProviderType::LlamaServer`를 추가한다.
Ollama는 레거시로 병렬 유지 (기존 등록 provider 무효화 없음).

## Change Type

Add + Migrate (어댑터 레이어 교체, 도메인 로직 유지)

## 핵심 변경 원칙

```
llama-server 특성:
  - 프로세스 시작 시 모델 VRAM 로드 → cold start 짧음 (GGUF 로컬 캐시 전제, Phase 2)
  - 라이프사이클: 요청 시 시작 → 유휴 시 종료 (Phase 3 ProcessManager 구현)
  - Phase 1 범위: 외부 운영 가정 (이미 떠있는 llama-server URL 등록)
                  Phase 3에서 mode 컬럼(external | managed) + lazy 라이프사이클 추가
  - GET /health → {"slots_idle": N, "slots_processing": M}
  - POST /v1/chat/completions (OpenAI 호환)
  - --ctx-size 프로세스 기동 시 고정 → num_ctx SSOT 정렬 불필요

lifecycle 단순화 (Phase 1 외부 운영):
  Before: probe + /api/ps 폴링 + stall 감지 + coalescing (600줄)
  After:  GET /health → ok? → AlreadyLoaded (50줄)
  (managed 모드의 자동 start/stop 트리거는 Phase 3 ensure_ready 에서 추가)

라우팅 기준 변경:
  Before: VRAM 잔량(MB) — /api/ps 30s 주기 갱신
  After:  slots_idle 수 — /health 즉시 응답
```

## LlamaServerAdapter 설계

```rust
// ensure_ready: health check만
async fn ensure_ready(&self, _model: &str) -> Result<LifecycleOutcome, LifecycleError> {
    let slots = self.health().await?;
    match slots {
        SlotStatus::Ok { .. } => Ok(LifecycleOutcome::AlreadyLoaded),
        SlotStatus::Loading    => Ok(LifecycleOutcome::AlreadyLoaded), // 시작 중
        SlotStatus::Failed     => Err(LifecycleError::ProviderError("unhealthy".into())),
    }
}

// stream_tokens: OpenAI SSE
fn stream_tokens(&self, job: &InferenceJob) -> Stream<StreamToken> {
    POST /v1/chat/completions { model, messages, stream: true }
    // data: {"choices":[{"delta":{"content":"..."}}]} 파싱
}

// infer: OpenAI non-streaming
async fn infer(&self, job: &InferenceJob) -> Result<InferenceResult> {
    POST /v1/chat/completions { model, messages, stream: false }
}
```

## slots_idle + Prefix-aware 라우팅

```rust
async fn get_llama_server_slots(provider: &LlmProvider) -> SlotSnapshot {
    GET {url}/health
    GET {url}/slots          // llama-server 슬롯별 prompt cache 상태
    // 반환: { slots_idle, slots_processing, slot_prefixes: Vec<TokenPrefix> }
}

// pick_best_provider LlamaServer 분기 (Prefix-aware):
// score = slots_idle × (1 + 5 × prefix_match_score)
//   prefix_match_score = max overlap (request prompt prefix vs slot.cached_prefix) / request_tokens
// slots_idle 동률 시 prefix 일치 큰 인스턴스 우선
//
// 효과: vibe coding 워크로드에서 system prompt + tool 정의 KV cache 재사용 → TTFT 큰 폭 단축
```

## 표준 메트릭 어휘 (vLLM/IGW 호환)

도입 메트릭 이름 — Grafana 대시보드 바로 호환:

| 메트릭 | 타입 | 설명 |
|--------|------|------|
| `time_to_first_token_seconds` | histogram | TTFT (요청 → 첫 토큰) |
| `inter_token_latency_seconds` | histogram | ITL (토큰 간 지연) |
| `inference_request_duration_seconds` | histogram | E2E 응답 시간 |
| `queue_depth` | gauge | provider_id 별 대기 요청 수 |

| `prefix_cache_hit_ratio` | gauge | 요청 prefix 가 캐시 hit 한 비율 |
| `cold_start_count` | counter | provider_id × model 별 cold start 횟수 |
| `cold_start_duration_seconds` | histogram | Loading→Ready 소요 시간 |
| `slots_idle` / `slots_processing` | gauge | 기존 slots 메트릭 |
