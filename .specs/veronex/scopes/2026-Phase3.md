## 핵심 플로우

```
POST /v1/models/load { model: "Qwen/...", quantization: "q4_k_m", ctx_size: 32768 }
  │
  ├── 1. ModelStore.resolve_model() → LocalModelPath   (Phase 2)
  │
  ├── 2. ProcessManager.find_available_gpu() → GpuSlot
  │     → GPU VRAM 확인, 온도 확인 (Thermal 게이트)
  │
  ├── 3. ProcessManager.start(model_path, config)
  │     → llama-server 바이너리 확인 (없으면 자동 설치)
  │     → 포트 할당 (ephemeral port pool)
  │     → Command::new("llama-server").args([...]).spawn()
  │     → GET /health 폴링 (최대 30s, GGUF 이미 로컬에 있으므로 빠름)
  │
  ├── 4. LlmProvider DB 자동 등록 (url = http://localhost:{port})
  │     → ProviderType::LlamaServer
  │     → 기존 라우팅 즉시 활용 가능
  │
  └── 5. 응답: { provider_id, port, status: "running" }
```

## 신규 모듈 구조

```
infrastructure/outbound/process_manager/
├── mod.rs
├── binary.rs         # llama-server 바이너리 관리
│   - check_installed() -> bool
│   - install(version) -> Result  (GitHub Releases API)
│   - binary_path() -> PathBuf
│   - LLAMA_SERVER_VERSION 상수
├── process.rs        # 프로세스 생명주기
│   - LlamaServerProcess { pid, port, model_path, config }
│   - start(config) -> Result<Self>
│   - stop() -> Result
│   - health() -> SlotStatus
│   - wait_healthy(timeout) -> Result
├── port_pool.rs      # 포트 관리
│   - allocate() -> u16 (11430~11530 범위)
│   - release(port)
└── manager.rs        # 전체 오케스트레이터
    - ProcessRegistry: DashMap<ProviderId, LlamaServerProcess>
    - load_model(model_path, config) -> Result<LlmProvider>
    - unload_model(provider_id) -> Result
    - list_running() -> Vec<ProcessInfo>
    - auto_recover() (프로세스 크래시 감지 + 재시작)
```

## llama-server 시작 파라미터

```bash
llama-server \
  --model {model_path}          # GGUF 파일 경로
  --ctx-size {ctx_size}         # 컨텍스트 크기 (기본 32768)
  --parallel {parallel}         # 동시 슬롯 수 (AIMD가 조정)
  --port {port}                 # 할당된 포트
  --no-mmap                     # 메모리 맵 비활성화 (상시 로드)
  --host 127.0.0.1             # 로컬 바인딩 (게이트웨이가 앞에서 노출)
  --gpu-layers {n_gpu_layers}   # GPU 레이어 수 (-1 = 전부 GPU)
  --threads {cpu_threads}       # CPU 스레드 수
```

## Ollama 코드 정리 (Phase 3에서 제거)

## 새 API 엔드포인트

```
POST /v1/inference/load
     { hf_repo, quantization, ctx_size, parallel, gpu_layers }
     → 202 { job_id }  (모델 로드 시작, SSE로 진행 확인)

GET  /v1/inference/load/{job_id}/status
     → { phase: "downloading|starting|running", progress... }

DELETE /v1/inference/{provider_id}
     → 프로세스 종료 + provider 제거

GET  /v1/inference/running
     → 현재 실행 중인 llama-server 목록 (pid, port, model, slots)
```

## 자동 복구 (Auto-Recovery)

```
background loop (10s):
  for process in registry:
    if !process.is_alive():
      log warn "process {pid} died, restarting"
      restart(process.config)  // 모델 이미 로컬에 있으므로 30s 내 복구
```
