# Scope: 2026-Phase2 — Modelfile Registry + CAS Blob Store

> L2: 승인 필요 | roadmap.md Phase 2 파생 | **Created**: 2026-05-09 | **Updated**: 2026-05-09
> **Dependency**: Phase 1 완료 후 진행

## Change Summary

Veronex 가 직접 GGUF 모델을 등록·관리하는 **Modelfile registry + CAS (content-addressable) blob store** 를 구현한다.

- Modelfile = 가벼운 메타 (chat_template, runtime params, system_prompt 등) + GGUF 참조 (sha256)
- GGUF 바이너리는 sha256 기반 dedup → 동일 GGUF 의 다른 메타 변경은 네트워크 0
- Source 4종 지원: HuggingFace / Direct upload / URL / S3 pointer
- Storage: k8s 내부 Garage S3 (CAS) + 노드별 Local PV (LRU 캐시)
- 설치 1회 실패 → install_status='failed' 즉시 고정, **자동 재시도 X, admin manual retry only**
- 등록되지 않은 모델 ID 추론 요청 → 404 (registration-only SSOT)
- 압축 버전(quantization)별 row 분리 + `family` 의 default 지정 가능

## 핵심 개념

### Modelfile vs GGUF Blob 분리

```
[GGUF 바이너리]   무거움(GB), 공통, 불변 (sha256 키)
   ▲
   │ FK 참조
   │
[Modelfile]       가벼움(KB), 사용자별 다름
   - chat_template, system_prompt, stop_tokens
   - runtime (n_ctx, n_gpu_layers, flash_attn, cache_type_k/v ...)
   - defaults (temperature, top_p, ...)
   - is_default (family 내 기본 promote)
```

### Content-Addressable Storage (CAS)

```
Garage S3 (k8s 내부, 클러스터 SSOT):
  veronex-models/
    gguf-blobs/{sha256}.gguf       ← 실제 바이너리, 전역 dedup

Local PV (노드별, /var/veronex/models):
  blobs/{sha256}.gguf               ← LRU 캐시, sha256 단위
```

→ 동일 sha256 은 cluster 전체에서 1개. ref_count=0 되어도 자동 삭제 X (admin 수동).

### 압축 버전 관리

```
model_id = "{family}:{quantization}"
예: qwen3-coder:q4_K_M, qwen3-coder:q5_K_M, qwen3-coder:q8_0

요청 매핑:
  POST /v1/inference  model="qwen3-coder:q4_K_M"  → 정확한 row
  POST /v1/inference  model="qwen3-coder"         → is_default=true row
  POST /v1/inference  model="qwen3-coder:foo"     → 404
```

워크플로우: 같은 family 의 여러 quant 등록 → 벤치 → `is_default` 토글로 promote.

## DB 스키마

### gguf_blobs (CAS)

```sql
CREATE TABLE gguf_blobs (
  sha256          TEXT PRIMARY KEY,
  size_bytes      BIGINT NOT NULL,
  s3_key          TEXT NOT NULL,            -- "gguf-blobs/{sha256}.gguf"
  source_history  JSONB NOT NULL,           -- [{type:"hf", repo, filename, fetched_at}, ...]
  ref_count       INT NOT NULL DEFAULT 0,
  orphan_since    TIMESTAMPTZ,              -- ref_count 1→0 시 set, 0→1+ 시 NULL
  created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
  last_accessed_at TIMESTAMPTZ
);
CREATE INDEX ON gguf_blobs (orphan_since DESC NULLS LAST) WHERE ref_count = 0;
```

### veronex_models (Modelfile)

```sql
CREATE TABLE veronex_models (
  model_id           TEXT PRIMARY KEY,           -- "{family}:{quantization}"
  family             TEXT NOT NULL,
  quantization       TEXT NOT NULL,              -- q4_0 | q4_K_M | q5_K_M | q8_0 | f16 | ...
  blob_sha256        TEXT NOT NULL REFERENCES gguf_blobs(sha256),
  display_name       TEXT,
  source_spec        JSONB NOT NULL,             -- 등록 시점 출처 (재현용)
  runtime            JSONB NOT NULL,             -- {n_ctx, n_gpu_layers, n_batch, flash_attn,
                                                 --  split_mode, cache_type_k, cache_type_v, ...}
  defaults           JSONB NOT NULL,             -- {temperature, top_p, top_k, repeat_penalty,
                                                 --  min_p, mirostat}
  chat_template      JSONB NOT NULL,             -- {type: "preset"|"jinja_inline"|"jinja_file",
                                                 --  value: ...}
  stop_tokens        JSONB,
  system_prompt      TEXT,
  is_default         BOOLEAN DEFAULT false,
  install_status     TEXT NOT NULL,              -- pending | downloading | uploading
                                                 --   | verifying | ready | failed
  last_error_kind    TEXT,
  last_error_message TEXT,
  last_attempt_at    TIMESTAMPTZ,
  tags               TEXT[],
  created_at         TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at         TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE (family, quantization)
);
CREATE UNIQUE INDEX ON veronex_models (family) WHERE is_default = true;
CREATE INDEX ON veronex_models (family);
CREATE INDEX ON veronex_models (install_status);
```

## 설치 FSM — 1회 실패 → admin manual retry only

```
[POST /v1/admin/models]
  ▼
veronex_models row 생성 (install_status='pending')
install_attempts row #1 생성 (status=in_progress, triggered_by='register')
  ▼
[Source 사전 sha256 조회]
  - hf:         LFS API 로 OID(sha256) 미리 조회   → ✅ 사전 가능
  - upload:     첫 chunk 직전엔 미상 (스트리밍 중 계산)
  - url:        HEAD 요청으로 ETag/Content-Length (sha256 미상 가능성 있음)
  - s3_pointer: HEAD 로 ETag/sha256 메타 확인     → ✅ 사전 가능
  ▼
[gguf_blobs lookup by sha256]   ← CAS dedup 게이트
  ├── EXISTS (CAS hit)
  │     - blob_sha256 = 기존 sha256
  │     - gguf_blobs.ref_count++, orphan_since = NULL
  │     - install_status='ready'
  │     - install_attempts → status='succeeded'
  │     ★ 다운로드 skip, 네트워크 ~KB ★
  │
  └── NOT EXISTS
        - install_status='downloading'
        - source 어댑터로 streaming → Garage 업로드 (sha256 누적 계산)
        - install_status='uploading' (옵션, source.upload 일 때만)
        - install_status='verifying' → sha256 검증
        ├── 성공 → gguf_blobs row 생성 (ref_count=1)
        │         install_status='ready', attempts → 'succeeded'
        │
        └── 실패 → install_status='failed'  ★ 자동 재시도 X ★
                    last_error_kind/message 캐시
                    install_attempts → 'failed'
                    admin [Retry] 클릭 시 attempt_no++ 새 row + 재시도
```

## error_kind 분류 (재시도 가능성은 admin UI hint, 자동 재시도 없음)

| error_kind | retryable hint | 의미 |
|------------|----------------|------|
| `network` | ✅ | timeout, connection reset, DNS fail |
| `rate_limit` | ✅ | HF 429 |
| `s3_error` | ✅ | Garage 일시 장애 |
| `sha256_mismatch` | ✅ | 다운로드 손상 |
| `timeout` | ✅ | 다운로드 stall |
| `unknown` | ✅ | 분류 안된 panic |
| `source_404` | ❌ | repo/file 없음 → Modelfile source 수정 필요 |
| `auth` | ❌ | HF token 필요·만료 |
| `disk_full` | ❌ | PV 용량 부족 |
| `invalid_gguf` | ❌ | 파일 손상·형식 오류 |
| `quantization_unsupported` | ❌ | llama.cpp 미지원 quant |

## Source 어댑터 4종

| Source | 용도 | 사전 sha256 | 비고 |
|--------|------|------------|------|
| `hf` | HuggingFace repo + filename + revision | ✅ LFS OID API | revision=commit hash 권장 (재현성) |
| `upload` | Admin UI multipart 업로드 | ❌ 스트리밍 계산 | 자체 quantize 결과물용 |
| `url` | 임의 HTTPS URL | ⚠️ HEAD 가능 시 ETag | 비공식 미러·내부 모델 서버 |
| `s3_pointer` | Garage 에 외부 도구로 미리 올린 객체 등록만 | ✅ HEAD ETag | 다운로드·업로드 모두 0 |

```json
{ "type": "hf",

  "filename": "qwen3-coder-7b-q4_k_m.gguf",

```

## Garage S3 + Local PV

### Garage 도입 (k8s 내부, Rust 단일 바이너리)

- Rust 구현, MinIO 대비 경량 (메모리·CPU)
- Erasure coding (3+ 노드 자동 분산)
- S3 호환 API
- platform-gitops 에 별도 배포 (이번 SDD 의존성으로만 명시, 배포는 별 작업)

### Local PV (Longhorn 대체)

- StorageClass: `rancher.io/local-path` (또는 자체 local-pv StorageClass)
- DaemonSet 패턴: 노드마다 ephemeral PVC + nodeSelector
- 읽기 전용 GGUF 에 최적 (mmap 성능 + 노드별 독립 캐시)
- LRU eviction at 90% 용량 threshold
- 노드 evac → PV 유실 → Garage 에서 재 fetch (자동, 첫 추론 시 cold start)

### 다운로드 우선순위 (추론 시점)

```
ProcessManager 가 spawn 직전:
1. Local PV /blobs/{sha256}.gguf  → 즉시 mmap
2. Garage GET gguf-blobs/{sha256}.gguf → streaming → Local PV atomic write (.tmp → rename) → mmap
3. Garage 도 미존재 → 500 "Blob registered but artifact missing" (이상 상태, 알림)
```

→ HuggingFace fetch 는 **등록 시점에만**. 추론 시점에는 절대 HF 안 침.

## API

### Modelfile CRUD

```
POST   /v1/admin/models
  body: { family, quantization, source: {...}, runtime, defaults,
          chat_template, stop_tokens?, system_prompt?, is_default? }
  → 201 { model_id, install_status }   (async install 시작)

GET    /v1/admin/models?family=&install_status=&is_default=
  → [{ model_id, family, quantization, install_status,
       last_error_kind, last_error_message, ... }]

GET    /v1/admin/models/:model_id
  → 단건 + blob 정보 (sha256, size, ref_count) + 최근 attempts 5건

PATCH  /v1/admin/models/:model_id
  body: 변경할 필드만
  - source 변경 → install_status='pending' + 새 attempt
                  + 기존 blob ref_count-- (orphan 가능성)
  - 그 외 (runtime/defaults/chat_template/...) → DB UPDATE only
                  → 다음 ProcessManager 시작부터 적용 (재다운 없음)
  - family/quantization 변경 → 405 Method Not Allowed

DELETE /v1/admin/models/:model_id
  → veronex_models row 삭제, gguf_blobs.ref_count--
     ref_count=0 되면 orphan_since=now() (자동 삭제 X)
     install_attempts 는 영구 보관

POST   /v1/admin/models/:model_id/promote
  → is_default=true, family 내 다른 row 는 false

POST   /v1/admin/models/:model_id/upload
  → multipart streaming 업로드 (source.type=upload 일 때만)
  → sha256 누적 계산 + Garage 직접 streaming write
```

### Install attempts

```
GET    /v1/admin/models/:model_id/install/attempts
  → 최신 N건 (ORDER BY started_at DESC)

GET    /v1/admin/models/:model_id/install/stream
  → SSE — bytes_downloaded/total_bytes, stage 전이

POST   /v1/admin/models/:model_id/install/retry
  → install_status='failed' 일 때만
  → 새 attempt_no, triggered_by='admin_retry'

POST   /v1/admin/models/:model_id/install/cancel
  → 진행 중일 때만 → status='cancelled', install_status='failed'

DELETE /v1/admin/install_attempts?model_id=...
DELETE /v1/admin/install_attempts/:id
  → admin 수동 정리 (자동 GC 없음)
```

### Blob orphan 표시 + 수동 GC

```
GET    /v1/admin/blobs?orphan=true&order_by=orphan_since
  → [{ sha256, size_bytes, orphan_since, orphan_days,
       last_source: {repo, filename}, total_models_history: N }]

GET    /v1/admin/blobs/:sha256
  → 상세 + 과거 사용 이력 (이 blob 참조했던 model_id 목록)

DELETE /v1/admin/blobs/:sha256
  → ref_count > 0 이면 409 Conflict
  → orphan 이면 Garage + 모든 노드 Local PV 에서 제거

POST   /v1/admin/blobs/gc?older_than_days=N
  → ref_count=0 AND orphan_days >= N 인 blob 일괄 삭제 (admin 수동 호출)
```

### 추론 요청 시 install_status 처리 (Phase 3 lazy load 와 통합)

```
install_status:
  ready                                  → 정상 진행 (ProcessManager.ensure_running)
  pending|downloading|uploading|verifying → 503 + Retry-After
                                              + status_url
                                              + body { reason: "model_installing",
                                                       attempt_no, stage, progress_pct }
  failed                                 → 409 Conflict
                                              + body { reason: "install_failed",
                                                       error_kind, error_message,
                                                       retryable, retry_url }
```
